# CP Typing

競技プログラミング用の **Python タイピング練習ツール**。
VS Code / VSCodium と同じエディタエンジン（Monaco Editor）の上で動くので、
括弧の自動閉じ・自動インデント・入力補完が効いた状態のまま練習できます。

「補完を切った素の打鍵速度」ではなく、**実際にコンテストで書くときの速度**を測るのが狙いです。

ビルド不要の静的サイトなので、`index.html` を開くだけで動きます。

## 使い方

1. 上部で課題を選ぶ（カテゴリ 6 種 / 全 29 問）
2. 右側のエディタにお手本どおり打ち込む
3. 打ち終わると結果が出る

- <kbd>Tab</kbd> … 補完を確定
- <kbd>Ctrl</kbd>+<kbd>Space</kbd> … 候補を手動で開く
- <kbd>Esc</kbd> … やり直す
- 「貼り付け」ボタンから、自分のテンプレートや本番で詰まったコードを課題にできます

貼り付けは練習エディタ側では無効化してあります（打って覚えるため）。

## 測っているもの

| 指標 | 意味 |
|---|---|
| **実効速度 (cpm)** | 完成コードの文字数 ÷ 時間。補完を使うほど上がる = 実戦的な速度 |
| 生打鍵 (cpm) | 実際に押したキー数 ÷ 時間。指そのものの速さ |
| **補完効率 (×)** | 完成文字数 ÷ 実打鍵数。1.00 なら補完を使えていない、2.00 なら半分の打鍵で書けている |
| 正確度 (%) | ミス打鍵の割合 |

記録は課題ごとにブラウザの localStorage に残ります（サーバーには何も送りません）。

### 判定の仕組み

お手本と入力の **共通接頭辞の長さ**を進捗とみなしています。
これにより、自動で挿入された閉じ括弧を「まだ打っていないだけ」として正しく扱えます。

```
お手本   print("Yes")
入力     print(       →  ( を打つと ) が自動で入り、進捗は print( まで
入力     print("")    →  " を打つと " が自動で入る
入力     print("Yes") →  完成。) と " は一度も打っていない
```

ミス判定も同じ考え方で、
「自動挿入された閉じ括弧」と「自動インデントの余分な空白」は誤字に数えません。
ブロックを抜けるときにインデントを戻す <kbd>Backspace</kbd> は実機でも押すものなので、減点されません。

## 入力補助の設定

「設定」から個別に切り替えられます。実機に寄せるほど実戦的に、切るほど純粋な打鍵練習になります。

- 入力補完（IntelliSense）／自動で候補を開く
- **Enter でも補完を確定する** — 既定は **オフ**。VS Code の既定（`editor.acceptSuggestionOnEnter`）はオンですが、
  候補が開いたまま Enter を押すと改行が入らず、以降の行がまるごとずれます。実機に完全に合わせたいときだけオンに。
- 競プロ用スニペット
- 括弧・クォートの自動閉じ
- 自動インデント
- ミニマップ / フォントサイズ

### 補完の中身

型推論はしていません（Pyright を持ち込むと数 MB になるため）。代わりに:

- **このファイル内の識別子** — 最優先。`inv` → `inv_fact`、`che` → `check`
- Python 組み込み関数とキーワード
- `sys.` `collections.` `heapq.` `bisect.` `itertools.` `math.` `functools.` `string.` のメンバ
- `.` の後はよく使うメソッド（list / str / dict / set / deque / Counter）
- 競プロ用スニペット

主なスニペット:

| 入力 | 展開 |
|---|---|
| `li` | `list(map(int, input().split()))` |
| `nm` | `n, m = map(int, input().split())` |
| `si` | `import sys` + `input = sys.stdin.readline` |
| `fr` | `for i in range(n):` |
| `d4` | 4 近傍ループ |
| `adj` | 隣接リスト構築 |
| `bfs` / `dij` / `uf` / `sieve` | BFS / ダイクストラ / Union-Find / エラトステネスの篩 |

## 課題を足す

[`src/problems.js`](src/problems.js) の `RAW` 配列に追記するだけです。

```js
{
  id: 'graph-scc', category: 'graph', level: 3,
  title: '強連結成分分解',
  tags: 'SCC / DFS',
  code: `
n, m = map(int, input().split())
...
`,
},
```

インデントは自動で 4 スペースに正規化され、行末空白と末尾改行は削られます。
タブを含めても構いません。

## ローカルで動かす

```bash
python -m http.server 8765
# http://localhost:8765/
```

ES モジュールを使っているので `file://` では動きません。何らかの HTTP サーバー経由で開いてください。

## 構成

```
index.html            画面
assets/style.css      スタイル（VS Code Dark+ 寄せ）
src/app.js            進捗判定・計測・UI
src/python-assist.js  言語設定と補完プロバイダ
src/problems.js       課題データ
```

Monaco Editor 0.52.2 を cdnjs から読み込むだけで、依存パッケージもビルド手順もありません。

## 実装メモ

ハマった点を残しておきます。

- **Monaco の worker は `data:` URL では起動しない。** Chrome が拒否するため、
  同一オリジンの `blob:` URL 経由で `importScripts` する必要があります。
  失敗しても例外が出ないので、worker 依存の機能が無言で死にます。
- **自前の補完プロバイダを登録すると、Monaco 標準の単語ベース補完が出なくなる。**
  そのため、ファイル内の識別子は自前プロバイダから供給しています。
  副産物として、ローカル変数を組み込み関数より上に出す順位付けができるようになりました。
- **スニペットを `sortText` の最上位に置くと Enter が暴発する。**
  `n` と打っただけで `na` スニペットが選択されるため、組み込み関数より下げてあります。
